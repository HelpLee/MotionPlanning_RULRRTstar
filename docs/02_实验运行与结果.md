# 2. Experiments and result analysis / 三组实验与结果分析

先完成[环境与规划器注册](01_环境与规划器注册.md)。批量实验入口为 `experiment/run_experiment.py`；原始版本保存在 `archive/local_history_20250930/ur5_group.py`。以下命令在 Ubuntu 的两个终端执行。

Complete [environment setup and planner registration](01_环境与规划器注册.md) first. `experiment/run_experiment.py` is the batch entry point; the original source is preserved at `archive/local_history_20250930/ur5_group.py`. Use two Ubuntu terminals for the commands below.

## 2.1 Share the parameter CSV / 统一参数 CSV 路径

两个终端都设置相同的 `RUL_DATA_DIR` 和 `RUL_CSV_PATH`。Python 在每次规划前写入六个 RUL、六个 gamma 和四个系数；C++ 规划器读取同一个 `rul.csv`。新输出统一放到仓库外，避免混入包内的 2025 年数据。

Set identical `RUL_DATA_DIR` and `RUL_CSV_PATH` values in both terminals. Before planning, Python writes six RUL values, six gamma values, and four coefficients. The C++ planner reads that shared `rul.csv`. Place new outputs outside the repository so the packaged data remain separate.

```bash
export REPO="$HOME/MotionPlanning_RULRRTstar"  # replace with the actual absolute path / 改为实际绝对路径
export RUL_DATA_DIR="$HOME/rulrrtstar_results/run_01"
export RUL_CSV_PATH="$RUL_DATA_DIR/rul.csv"
mkdir -p "$RUL_DATA_DIR"
source /opt/ros/melodic/setup.bash
source "$HOME/ws_moveit/devel/setup.bash"
```

每个完整批次使用独立输出目录，例如下一批改为 `run_02`。 / Use a separate output directory for each full batch, such as `run_02` for the next one.

## 2.2 Start UR5 MoveIt / 启动 UR5 MoveIt

在**终端一**执行上述环境设置，然后启动 MoveIt。 / In **terminal 1**, apply the environment settings above and start MoveIt:

```bash
roslaunch ur5_moveit_config demo.launch
```

这是 UR5 的 fake-execution 场景；实验脚本只调用 `move_group.plan()`，原始代码中的 `move_group.execute()` 是注释状态。`/joint_usage` 与 `/joint_loss` 来自规划器对生成路径的计算。

This launch uses UR5 fake execution. The runner calls `move_group.plan()`; `move_group.execute()` is commented out in the original code. The planner derives `/joint_usage` and `/joint_loss` from planned paths.

可在另一个终端检查 ROS 状态。 / Inspect the ROS state from another terminal:

```bash
source /opt/ros/melodic/setup.bash
source "$HOME/ws_moveit/devel/setup.bash"
rosnode list | grep move_group
rosparam list | grep planner_configs
rostopic list | grep joint_
```

`/joint_usage` 和 `/joint_loss` 可能在首次规划之后出现。 / These topics may appear only after the first planning request.

## 2.3 Run the batch / 运行批次

在**终端二**执行第 2.1 节同一组环境设置，然后运行脚本。 / In **terminal 2**, apply the same environment and start the runner:

```bash
python2 "$REPO/experiment/run_experiment.py"
```

程序按 LDS → FHS → HDS 的顺序运行。每个场景先运行 `RULRRTstar`，再运行 `BaseRRTstar`；每种规划器依次遍历 `p=0.8,1.0,1.5`，每个 `p` 重复三次。每次运行重置 RUL、gamma 和输出文件，然后对取物与放物姿态分别规划；成功完成一个任务后更新 RUL、gamma，检查停止条件。

The runner processes LDS → FHS → HDS. Within each scenario it runs `RULRRTstar` and then `BaseRRTstar`; each planner covers `p=0.8,1.0,1.5` with three runs per shape. A run resets RUL, gamma, and output files, plans pickup and place poses, updates RUL and gamma after each completed task, and evaluates the stopping rule.

主要参数集中在脚本顶部。 / The main settings are grouped near the top of the script:

| Parameter / 参数 | Value / 设置 |
| --- | --- |
| `SHAPE_LIST`, `RUNS_PER_SHAPE` | `[0.8,1.0,1.5]`，`3` |
| `SEED` | `42` for Python `random` and NumPy / 用于 Python 与 NumPy |
| `PLANNING_GROUP` | `manipulator` |
| `PLANNING_TIME`, `PLANNING_ATTEMPTS` | `5.0` seconds, `1` attempt / 5 秒、1 次 |
| `ALPHA_INIT`, `LAMBDA_INIT`, `RULMIN_PARAM` | `1.0`，`1.0`，`1.0` |
| `EPSILON_INIT` | Python value `1e-9`; `0.0` after two-decimal CSV rounding / 写入 CSV 后为 `0.0` |
| `min_rul` | `10` |
| `XMAX_PER_JOINT` | `1000` for each joint / 六关节均为 `1000` |
| Pickup / place sampling bounds / 取放姿态范围 | X `[0.15,0.55]`; pickup Y `[-0.50,-0.35]`; place Y `[0.40,0.55]`; Z `[0.10,0.20]` |

场景初始值和任务上限如下。 / Scenario initial states and task limits are:

| Scenario / 场景 | Initial RUL / 初始 RUL | Task limit / 任务上限 |
| --- | --- | ---: |
| LDS | `[100,1000,1000,1000,1000,1000]` | 500 |
| FHS | `[1000,1000,1000,1000,1000,1000]` | 80 |
| HDS | `[500,800,400,600,1000,700]` | 80 |

LDS 通常由 `min_rul` 条件在 500 个任务之前停止。初次检查接线时，可以在 `run_experiment.py` 的工作副本中缩小 `SHAPE_LIST`、`RUNS_PER_SHAPE` 和 `max_tasks_value`；正式批次使用表中设置。

LDS generally stops on `min_rul` before reaching 500 tasks. For an initial integration check, reduce `SHAPE_LIST`, `RUNS_PER_SHAPE`, and `max_tasks_value` in a working copy of `run_experiment.py`; restore the table values for a full batch.

## 2.4 Interpret the outputs / 读取输出

运行后列出输出文件。 / List the files after the batch:

```bash
find "$RUL_DATA_DIR" -type f -name '*.csv' | sort | head -30
```

每个场景目录中，`rul-aware_0.8_1.csv` 这样的主文件记录每次更新后的六个 RUL、六个 gamma 和 `lambda,alpha,rulmin,epsilon`，共 16 列；同名的 `_joint_usage.csv` 和 `_joint_loss.csv` 分别保存 pickup/place 的关节用量与损失。`base_*` 是对照规划器，命名规则相同。原始 `BaseRRTstar` 只发布 `/joint_usage`，不发布新的 `/joint_loss`；对照组的 loss 文件可能收到上一次 RUL-aware 规划器留下的 latched 话题值，**不要把 `base_*_joint_loss.csv` 当作独立测量的 Base 损失**。对照任务数与 RUL 轨迹以其主 CSV 和 usage 文件读取。

Within each scenario, a main file such as `rul-aware_0.8_1.csv` stores six RUL values, six gamma values, and `lambda,alpha,rulmin,epsilon` in 16 columns. The paired `_joint_usage.csv` and `_joint_loss.csv` store pickup/place values; `base_*` follows the same naming scheme. `BaseRRTstar` publishes `/joint_usage` but no new `/joint_loss`. Its loss file may therefore receive a latched value from a preceding RUL-aware run. **Do not interpret `base_*_joint_loss.csv` as an independent Base loss measurement.** Use its main and usage files for Base task counts and RUL trajectories.

一个完整批次应有 **54 个主 CSV + 54 个用量 CSV + 54 个损失 CSV**，分布在三个场景目录中。运行中的共享输入文件 `rul.csv` 位于 `RUL_DATA_DIR` 根目录，不属于某一次实验的最终导出。

A full batch produces **54 main, 54 usage, and 54 loss CSVs** across three scenario directories. The shared input `rul.csv` sits at the root of `RUL_DATA_DIR` while the experiment runs; it is separate from the per-run exports.

## 2.5 Generate the experiment summary / 生成实验汇总

`data/joint_usage_1/` contains the three-scenario CSVs and saved summaries. Run the following from the repository root on any Python 3 machine. / 包内已提供三组数据和统计文件，可在任意 Python 3 环境执行：

```bash
python3 analysis/experiment_table.py --check-stored-summary
python3 analysis/check_gamma_trace.py  # 需要 numpy
```

第一条命令按场景、规划器、`p` 汇总三次运行的最终最弱关节 RUL、六关节 RUL 总和、平均完成任务数和标准差。输出的 FHS/HDS 各组任务数是 80；LDS 的 Base → RUL-aware 平均任务数依次为 `18.67→27.67`、`33.00→51.67`、`73.67→111.67`。

The first command aggregates three runs per scenario/planner/shape into weakest-joint final RUL, six-joint RUL sum, mean completed tasks, and sample standard deviation. FHS/HDS groups complete 80 tasks. LDS mean tasks, Base → RUL-aware, are `18.67→27.67`, `33.00→51.67`, and `73.67→111.67`.

安装 Matplotlib 后，运行 `python3 analysis/plot_summary.py --out results/summary.png`，可从 54 次原始运行生成三场景的任务数和最弱关节最终 RUL 对比图。

With Matplotlib installed, `python3 analysis/plot_summary.py --out results/summary.png` generates a three-scenario comparison of task count and weakest-joint final RUL directly from the 54 runs.
